MEDITRACK FRONTEND BACKEND HANDOFF
==================================

The frontend integration is wired to the API contract in API_INTEGRATION.txt.

Environment
-----------
Set NEXT_PUBLIC_API_URL to the backend origin, for example:
NEXT_PUBLIC_API_URL=http://localhost:5000

Authentication
--------------
- Better Auth requests use credentials: include.
- The frontend expects the Better Auth session cookie to be set by the API.
- Next.js proxy.ts performs an optimistic cookie check for /admin routes.
- The client also calls /api/auth/get-session. The backend remains authoritative.
- The current user role is read from session.user.role. Use the exact "admin" value
  to expose mutation controls; all mutations still handle HTTP 403.

Implemented API calls
---------------------
- GET /api/dashboard
- GET /api/doctors with page, limit, search, specialization
- POST/PATCH/DELETE /api/doctors
- GET /api/doctors/:id/patients
- GET /api/patients with page, limit, search, condition, doctorId
- POST /api/patients/doctor/:doctorId
- PATCH/DELETE /api/patients/:id

Expected response details
-------------------------
- Collection responses must include data and pagination.page, limit, total.
- Doctor list items must include patientCount.
- Patient doctorId should be the populated doctor object in patient responses.
- DELETE success must return HTTP 204 with an empty body.
- Error responses should use { "error": "..." } so the frontend can display the
  backend message, especially 401, 403, 404, 409, and validation errors.

Validation / test checklist
---------------------------
- Verify CORS allows the frontend origin and credentials.
- Verify the session cookie is available to cross-origin fetches.
- Verify non-admin authenticated users can read but receive 403 on mutations.
- Verify deleting a doctor with patients returns the documented 409 message.
- Verify seed:admin has been run for local development.
